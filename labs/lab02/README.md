# Лабораторна робота №2. ООП, регулярні вирази та аудит конфігурацій

## Завдання 1. Система автентифікації та аудиту (task1.py)

### Що робить
Моделює систему авторизації користувачів, обробки сесій та логування подій.
- Клас User: зчитує та валідує email через регулярні вирази, хешує пароль за допомогою PBKDF2-HMAC-SHA256 із сіллю та перевіряє його через hmac.compare_digest.
- Клас Admin: успадковує User, додає управління правами (permissions).
- Клас Session: контролює час активності користувача та таймаут сесії.
- Класи AuditLog та LogEntry (dataclass): накопичують і виводять лог подій.
- Клас UserAccount: об'єднує користувача, сесію та лог; реалізує доступ до полів через магічні методи __getitem__ та __setitem__ з перевіркою типів (isinstance).

### Запуск
```bash
python -m labs.lab02.task1
```

## Завдання 2. Аналізатор правил фаєрволу (task2.py)

### Що робить
Проводить багаторівневу обробку та аудит JSON-файлу з правилами фаєрволу:
1. Зчитує JSON-файл з конфігурацією.
2. Перевіряє коректність IP-адрес та CIDR-масок за допомогою регулярних виразів (sort_rule).
3. Групує правила за сукупним ключем (source, destination, port) за допомогою defaultdict.
4. Видаляє дублікати (правила з однаковими діями) та відсіює конфлікти (однакові напрямки з різними діями ALLOW/DENY).
5. Виявляє потенційно небезпечні правила (ALLOW з відкритим джерелом 0.0.0.0/0, ANY або відкритими портами ANY, *).
6. Зберігає очищений список правил у новий JSON-файл та виводить текстовий звіт у консоль.

### Структура проектних файлів
```text
labs/lab02/
├── data/
│   ├── firewall_rules.json
│   └── cleaned_rules.json
├── task1.py
└── task2.py
```

### Вхідні дані
Файл `labs/lab02/data/firewall_rules.json` містить масив правил наступної структури:
```json
[
  {
    "id": 1,
    "source": "10.0.0.0/8",
    "destination": "192.168.10.10",
    "port": "443",
    "action": "ALLOW"
  },
  {
    "id": 8,
    "source": "ANY",
    "destination": "10.0.0.1",
    "port": "ANY",
    "action": "ALLOW"
  }
]
```

### Запуск
Стандартний запуск:
```bash
python -m labs.lab02.task2
```

Запуск із параметрами командного рядка (CLI):
```bash
python -m labs.lab02.task2 --rules-file data/firewall_rules.json --output data/cleaned_rules.json --check-conflicts
```

### Вихідні дані та що виведе
1. Створюється файл `labs/lab02/data/cleaned_rules.json` із відфільтрованим списком валідних правил.
2. У консоль виводиться текстовий звіт наступного вигляду:

```text
=======================================================
           FIREWALL RULES AUDIT REPORT           
=======================================================

[СТАТИСТИКА ПЕРЕВІРКИ]
  • Всього завантажено правил:       15
  • Невалідні IP / Маски (видалено): 2
  • Дублікати (видалено повторки):  3
  • Конфліктні правила (відсіяно):  1
  -------------------------------------------------
  • Залишилось валідних правил:      9

[ПОТЕНЦІЙНО НЕБЕЗПЕЧНІ ПРАВИЛА (HIGH-RISK)]
  [HIGH-RISK] Rule #8: ALLOW ANY -> 10.0.0.1:ANY (Unlimited exposure (Public Source), All ports allowed (ANY port))

=======================================================
```
